## Companion terrain protection

- Track supported Twilight Forest, Aquamirae, and Mowzie soul attacks and their
  projectile provenance. Filter mob-griefing/block effects and affected explosion
  blocks for those sources, retaining native entity-damage paths.
- Cover version-matched Twilight direct terrain effects, block transformations,
  plant growth, ice breaking, and falling-ice creation/landing. Protected falling
  ice must not remove its source block, place a replacement, or drop that block.
- Suppress Aquamirae Maze Mother's direct ice-breaking operation for owned souls.
- Resolve Mowzie ice-breath casters through the native public method or legacy
  field and suppress its block-freezing operation for supported companion casts.
- On matching newer Mowzie APIs, prevent the Sculptor's terrain-clearing trade test
  on 1.19.2 and Elokosa leap-marker block swaps on 1.20.1, retaining the leap result.

These rules apply to supported owned souls/attacks, not wild mobs globally. They
do not claim every third-party attack or terrain-writing path is covered. Existing
Ice and Fire terrain/form/preview protections, Hydra previews, Twilight descendant
ownership, Mowzie ally filtering, Aquamirae music hooks, and friendly Siren charm/
appearance corrections remain. The dedicated Wroughtnaut activation adapter stays
removed.

## Installation and portable development

Install the matching core and addon for the selected Minecraft version on both
sides, plus selected creature mods and libraries. The addon bundles neither core
nor third-party code/assets. The accepted core versions are **1.3.0** and
**1.3.0-prerelease** for the matching Minecraft version; stable 1.2.3 users should
keep Compat 1.2.3.

Configure an installable core runtime JAR in ignored `local.properties`, e.g.:

```properties
soulcatcherplusJar=C:/Minecraft/mods/soulcatcherplus-1.3.0+1.16.5.jar
```

`-PsoulcatcherplusJar=<path>` overrides that setting. No adjacent core checkout is
needed. Use the matching branch/JDK and bootstrap/build commands from the README;
legacy projects remap the JAR with `fg.deobf`, while 26.3 uses its unobfuscated JAR
directly. Core development stays independent of addon sources and builds.
